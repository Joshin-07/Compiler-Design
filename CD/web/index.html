How the C parser enforces precedence & left-associativity

EBNF Grammar Rules (in parser.c)

expr   -> term   (('+' | '-') term)*      // Lowest precedence, left-associative
term   -> factor (('*' | '/') factor)*    // Higher precedence, left-associative
factor -> NUMBER | IDENTIFIER 
        | '(' expr ')'                    // Parentheses reset to expr
        | '-' factor                      // Highest precedence (unary prefix)

Case Study: 2 + 3 * 4

1
expr() is called: it must first parse a term() for its left-hand side.
2
term() parses 2: looks ahead at +. Since + is not * or /, term() returns the leaf 2 immediately back to expr().
3
expr() consumes +: now calls term() to parse the right-hand side.
4
term() parses 3: sees the upcoming * operator. Because multiplication is handled inside term(), it eagerly binds 3 * 4 before returning!
✓
Final Tree: + has children 2 and (3 * 4). Multiplication binds tighter naturally without operator tables!
